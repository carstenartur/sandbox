Using Method Reuse

Entry point and modes

Open Java > Code Style > Clean Up, edit a dedicated profile, and select Method Reuse (Sandbox).

  • Find reusable method patterns analyzes method-level duplication candidates.
  • Find inline code sequences that can be replaced with method calls replaces a proven inline expression or statement sequence with an existing compatible method invocation.

Proven inline-sequence example

Before

String formatName(String first, String last) {
    return first.trim() + " " + last.trim();
}

void printUser(String firstName, String lastName) {
    String name = firstName.trim() + " " + lastName.trim();
    System.out.println(name);
}

After

String formatName(String first, String last) {
    return first.trim() + " " + last.trim();
}

void printUser(String firstName, String lastName) {
    String name = formatName(firstName, lastName);
    System.out.println(name);
}

Applicability

The replacement is offered only when variable mapping, argument evaluation order, return value, visibility, static or instance context, and side-effect analysis support the same observable behavior. Merely similar token text is not sufficient. Ambiguous overloads, inaccessible methods, escaping intermediate values, unresolved bindings, or additional side effects leave the source unchanged.

This cleanup remains experimental. Treat every candidate as a refactoring proposal to review, not as proof that two arbitrary algorithms are equivalent.

Review the real execution preview

  1. Enable only one Method Reuse mode while evaluating its candidates.
  2. Run Source > Clean Up... on a small source selection.
  3. Inspect the removed inline statements, mapped arguments, receiver, imports, and selected overload.
  4. Compile and run tests covering nulls, exceptions, side effects, and invocation order.

The common standard-LTK file selection and code comparison are documented in Cleanup preview model.
