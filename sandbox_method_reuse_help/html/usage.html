Using Method Reuse

Entry point and modes

Open Java > Code Style > Clean Up, edit a dedicated profile, and select Method Reuse (Sandbox).

  • Replace exact duplicate static method implementations with existing method calls is a coordinated project cleanup. It finds an existing source method and replaces another whole method body with a delegation call only when both implementations are semantically identical under positional parameter substitution.
  • Find inline code sequences that can be replaced with method calls is the established local mode. It replaces a proven expression or statement sequence inside one compilation unit with an existing compatible method invocation.

Coordinated duplicate-method example

Before

final class CanonicalNames {
    static String normalize(String value) {
        return value.trim();
    }
}

final class Names {
    static String clean(String input) {
        return input.trim();
    }
}

After

final class CanonicalNames {
    static String normalize(String value) {
        return value.trim();
    }
}

final class Names {
    static String clean(String input) {
        return CanonicalNames.normalize(input);
    }
}

The host automatically expands the selected cleanup scope to the complete editable Java source project. The preview therefore includes every changed compilation unit in one LTK change, and Apply and Undo remain atomic. This coordinated mode is deliberately disabled for save actions.

Local inline-sequence example

Before

String formatName(String first, String last) {
    return first.trim() + " " + last.trim();
}

void printUser(String firstName, String lastName) {
    String name = firstName.trim() + " " + lastName.trim();
    System.out.println(name);
}

After

String formatName(String first, String last) {
    return first.trim() + " " + last.trim();
}

void printUser(String firstName, String lastName) {
    String name = formatName(firstName, lastName);
    System.out.println(name);
}

Applicability

The first coordinated slice accepts only whole static source methods in the same package and source root. Each method must contain one non-void return expression and have resolved bindings, matching return and parameter types, and an unambiguous accessible target. Fields or captured state, comments inside the body, generics, varargs, checked exceptions, synchronized/native/abstract methods, assignments, increments, object or array creation, lambdas, method references, recursion, this/super, and targets with static fields or initializers are rejected.

The local inline mode retains its separate variable-mapping and sequence checks. For both modes, merely similar text is insufficient: unresolved bindings, ambiguous overloads, inaccessible methods, changed evaluation order, or unsupported side effects leave the source unchanged.

Review the real execution preview

  1. Enable only one Method Reuse mode while evaluating its candidates.
  2. Run Source > Clean Up... on a small source selection.
  3. For coordinated delegation, review every automatically added source file and the selected canonical method.
  4. For inline replacement, inspect removed statements, mapped arguments, receiver, imports, and overload.
  5. Apply the complete preview and run the affected tests; use the single cleanup Undo if the result is unwanted.

The common standard-LTK file selection and code comparison are documented in Cleanup preview model.
