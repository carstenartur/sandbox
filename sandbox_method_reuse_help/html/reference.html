Method Reuse: reference

Coordinated duplicate-method mode

The cleanup expands the selected source scope through the shared multi-file cleanup host, creates one immutable project plan, and emits one local edit per affected compilation unit. Plans retain Java-model handles, binding keys, source identities, method signatures, and semantic fingerprints; they do not retain AST nodes.

Immediately before an edit is produced, the duplicate method and canonical target are resolved again from fresh source ASTs. A missing unit, changed binding, changed signature or fingerprint, inaccessible target, or incomplete source scope invalidates the candidate instead of producing a partial change.

Current applicability contract

  • Both methods are source methods in different compilation units of the same package and source root.
  • Both are static, binding-resolved, non-generic, non-varargs methods with matching parameter and return types.
  • Each body consists of one non-void return expression; target parameters map positionally to duplicate parameters.
  • Every non-parameter name resolves to the same method, type, or package binding in both expressions.
  • The canonical method is accessible and its declaring type has no static field or explicit static initializer.
  • The implementation contains no body comment, captured field, assignment, increment, object/array creation, lambda, method reference, recursion, switch expression, this, or super access.

Local inline-sequence mode

The second checkbox retains the existing same-compilation-unit sequence matcher. It identifies an existing method and a contiguous expression or statement sequence whose mapped arguments preserve evaluation order and observable behavior, then replaces only that local sequence.

Impact and host behavior

The coordinated mode has project-closed impact. It requires explicit Cleanup preview and is not eligible for save actions. The preview, Apply, and Undo operations are one standard LTK transaction across all affected files. The local inline mode remains independently selectable.

Known limitations

  • Multi-statement methods, instance receivers, local-variable normalization, cross-package delegation, generic methods, and call-site replacement are intentionally outside the first coordinated slice.
  • Semantic equivalence beyond the accepted AST and binding identity is not inferred.
  • Very large projects can be rejected by the shared planning budget rather than analysed incompletely.
  • Reuse candidates should still be reviewed for API ownership and readability.

Support information

The Help content is shipped with the same feature version as the runtime plug-in. When reporting a problem, include the Sandbox feature version, Eclipse version, Java version, the smallest reproducing source, and whether bindings were available.
