# Backblaze JavaReedSolomon external baseline

Frozen before running the benchmark. Pinned upstream: https://github.com/Backblaze/JavaReedSolomon/commit/d3c481dc69471e0c47ff6f67f33d53bde941675e.

* Measure only public ReedSolomon.encodeParity on each of the 12 unmodified CodingLoop.ALL_CODING_LOOPS. The normal upstream default is InputOutputByteTableCodingLoop. The initial input is a real encoder chosen separately from the rule-learning fixtures. This benchmark by itself measures upstream code.
* Calibration: 17 data + 3 parity shards, 200000 bytes per shard, offset 0 (upstream geometry). Reserve two further configurations: small 17+3, 4096 bytes, offset 7; large 10+4, 1048576 bytes, offset 13. All calls encode exactly the stated number of bytes excluding offsets. Allocate 11 untouched bytes after the encoded range. Fixed winner selection uses only highest median calibration throughput, lexicographic tie-break. Never retune on the two reserved configurations. They are held out only from choosing this upstream baseline.
* Use four deterministic input buffer sets, common random seed 381691 across designs, cyclic use. For each design independently verify that every buffer after one encode matches the default implementation byte for byte (including input and guards) with the same random input. After timing, check all buffers again with the upstream default plus full-array equality. Exit nonzero for any mismatch.
* Independently fork one JVM per (variant, geometry, repetition), three repetitions. Shuffle job order with Python seed 4711. One application thread. Fixed Java heap -Xms512m -Xmx512m and two JVM-visible processors to limit shared-runner noise. Each JVM warms up for at least 400 milliseconds, then measures three windows lasting at least 250 milliseconds each. All actual encoded calls count, including the last call crossing the time boundary. Single process at a time. No processor isolation assumed.
* Primary metric: payload throughput in decimal MB/s (data shards times bytes per shard over wall-clock time, excluding setup, reference checks and analysis). Aggregate windows per fork by total payload divided by total elapsed time. Report median of three fork rates plus min and max. Also report median ns per encode and median current-thread allocated bytes per encode from ThreadMXBean, when supported. Allocation includes the upstream public entry point; it excludes initialization and verification.
* Report all 12 variants, the existing upstream default, the calibration winner on both held-out workloads, and the best existing variant per configuration. No confidence intervals, statistical superiority or cross-host performance claim. A zero-patch external run has no measured candidate speedup.
