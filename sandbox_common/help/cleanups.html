Using Sandbox cleanups

Sandbox cleanups participate in the Eclipse JDT cleanup and quick-assist workflows. Availability depends on the installed Sandbox features and the Java source level of the project.

Configuration

  1. Open Window > Preferences > Java > Code Style > Clean Up, or the corresponding project-specific settings.
  2. Create or edit a cleanup profile.
  3. Enable only the transformations you intend to review together. Coordinated migrations such as JUnit hierarchy conversion may analyse several compilation units as one transaction.
  4. Use a project-specific profile when source level, libraries or migration policy differ between projects.

Ways to invoke transformations

  • Source > Clean Up applies the active profile to the selected scope.
  • Quick Assist proposes transformations for the current selection or problem location.
  • The Sandbox cleanup application can run supported cleanups in batch and check modes for reproducible command-line verification.
  • .sandbox-hint files can be opened in the Sandbox Hint Editor and executed through the TriggerPattern integration.

Review expectations

Always inspect the Eclipse preview or generated diff. A cleanup may be syntactically valid while still requiring project-specific judgement about API compatibility, ordering or runtime behaviour. Binding-dependent transformations are not offered when JDT cannot resolve the required types and members.

Atomic migrations

Multi-file migrations collect their expected inputs before rewriting. If the scope is incomplete, a plan target is stale, or exact rule coverage cannot be established, the migration is rejected rather than partially applied.
