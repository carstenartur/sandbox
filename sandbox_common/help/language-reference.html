Per-rule metadata

  • @id: stable.rule.id assigns a stable rule identity.
  • @severity: info|warning|error|hint overrides the program severity.
  • @kind: TYPE_DECLARATION selects an explicit pattern kind and requires @id.

Operators

::Attach a guard to a source pattern or alternative.
=>Ordinary text or pattern replacement.
=>!Ordered schema-validated structured actions.
;;Terminate one rule.
&&, ||, !Guard conjunction, disjunction and negation.

Binding-dependent guards

Guards such as instanceof, genericTypeIs and subtypeOf can report an unknown result when JDT cannot resolve the required binding. With binding-policy: optional or no explicit policy, the historical boolean compatibility value is used. With binding-policy: required, or whenever a semantic plan is installed, unknown means no rewrite and an actionable diagnostic.

Three-valued composition follows the information available: UNKNOWN || MATCH is MATCH, UNKNOWN && NO_MATCH is NO_MATCH, and negating UNKNOWN remains UNKNOWN.

Structured action target convention

The primary matched node is the implicit target. Add target=$binding only to operate on another bound node.

Standard structured actions

  • addAnnotation(annotation=VALUE [, value=VALUE] [, target=VALUE])
  • removeAnnotation(annotation=VALUE [, target=VALUE])
  • addModifier(modifier=VALUE [, target=VALUE])
  • removeModifier(modifier=VALUE [, target=VALUE])
  • removeSupertype(type=VALUE [, target=VALUE])
  • replaceSupertype(type=VALUE, replacement=VALUE [, target=VALUE])
  • removeDeclaration([target=VALUE])
  • qualifyInvocation(owner=VALUE [, target=VALUE])
  • renameDeclaration(name=VALUE [, target=VALUE])
  • replaceFieldType(type=VALUE [, target=VALUE])
  • addParameter(type=VALUE, name=VALUE [, index=VALUE] [, target=VALUE])
  • removeParameter(name=VALUE|index=VALUE [, target=VALUE])
  • replaceParameterType(type=VALUE, name=VALUE|index=VALUE [, target=VALUE])

For parameter selection, name is preferred because it remains stable when other parameters are inserted. index is an explicit positional escape hatch.

Important plan guards

plannedRole, enclosingPlannedRole, plannedValue, enclosingPlannedValue, plannedNodeValue, plannedListContains, plannedRelation, plannedRelationValue, plannedOutgoingRelation, plannedIncomingRelation and plannedRelationCount.

Compatibility note

The authoritative vocabulary is the runtime HintLanguageVocabulary, registered guard set and RewriteActionCatalog. This page is checked as product documentation, but implementations and extensions must derive editor completion and validation from those catalogs rather than parsing this HTML.
