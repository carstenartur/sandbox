Sandbox Hint DSL programmer's guide

A .sandbox-hint file is a versioned transformation program. It declares metadata, optional reusable predicates and one or more source-pattern rules with text replacements or schema-validated structured actions.

Minimal program

<!id: collections.empty-list>
<!description: Prefer List.of()>
<!minJavaVersion: 9>

Collections.emptyList()
=> java.util.List.of()
;;

Program directives

Common directives include id, description, severity, minJavaVersion, tags, include, caseInsensitive, suppressWarnings and treeKind. Advanced programs may declare map, foreach, local predicate definitions and a required semantic-plan contract with requires-plan.

Rule structure

@id: stable.rule.id
source-pattern :: sourceGuard($node)
=> replacement-pattern :: alternativeGuard($node)
=> fallback-pattern :: otherwise()
;;

Every production rule should have a stable @id. An explicit @kind also requires an ID. The source guard authorizes the match; each alternative may add another condition. The first matching alternative is selected.

Structured alternative

@id: add.test.annotation
void $method($params$) :: plannedRole($method, "TEST_METHOD")
=>! addAnnotation(target=$method,
        annotation="org.junit.jupiter.api.Test")
;;

=>! introduces ordered structured actions. They are parsed into typed values and executed through registered AST handlers; they are not fake Java replacement text.

Design rules

  • Match the smallest stable AST shape that expresses the transformation.
  • Use bindings and guards for semantic constraints rather than spelling variants.
  • Use a semantic plan when correctness depends on more than the local match.
  • Split text and structured alternatives into separate rules.
  • Treat parser acceptance, editor support, diagnostics and tests as one language contract.
