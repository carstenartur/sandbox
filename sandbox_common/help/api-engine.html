Engine architecture and lifecycle

1. Parse the complete program

Use HintProgramParser for a complete .sandbox-hint program. It preprocesses local predicates, explicit rule-kind metadata and structured-action alternatives, delegates compatibility syntax to the established parser, and rehydrates the result into one typed model. Program diagnostics should retain source lines and stable rule IDs.

2. Build or obtain the AST

The caller supplies a JDT CompilationUnit configured with the project compiler options. Binding-dependent rules require an AST created with the appropriate Java project, source path and class path. A syntax-only AST must not be presented as binding-complete.

3. Index and match

PatternIndex dispatches candidate nodes by PatternKind and avoids a fresh full-tree traversal for every rule. Specialized parsers and matchers own complex forms such as statement sequences and header-only type declarations. A Match retains the matched node and placeholder bindings.

4. Evaluate guards and alternatives

BatchTransformationProcessor evaluates source guards and selects the first applicable rewrite alternative. Its TransformationResult records the rule, match, replacement or structured actions and descriptive information. A result without a rewrite is not an operation.

5. Apply semantic-plan authorization

For coordinated migrations, install a SemanticRewritePlan with the compiler options. PlanAwareHintFileFixCore validates the required contract, rejects empty plans and analysis-dependent replacement shortcuts, and checks that every authorized match has a stable NodeKey.

6. Create rewrite operations

Text results are serialized into an action-free hint program and delegated to the established text rewrite backend. Structured results become StructuredRewriteActionOperation instances. The operation resolves its named arguments, verifies the target against the semantic plan and dispatches to the registered handler.

7. Apply AST and import rewrites

Handlers use one CompilationUnitRewrite transaction with ASTRewrite, ImportRewrite and text-edit groups. They must preserve comments and existing project formatting behaviour. Ambiguous declaration-wide field operations and unresolved static invocations are rejected.

8. Check coverage and verify behaviour

Plan-aware callers compare the produced operation targets with the expected planned targets. Multi-file cleanup infrastructure applies the transaction only when its complete scope is valid. Runtime-sensitive migrations then compare completed execution-tree snapshots under an explicit policy.

Threading and reuse

Immutable program, schema and plan objects may be shared. Mutable builders, AST nodes, rewrite objects and processing contexts belong to one operation. Registries must reject conflicting names and remain deterministic under concurrent reads.
