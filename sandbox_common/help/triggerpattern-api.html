TriggerPattern API programmer's guide

TriggerPattern separates the portable transformation language and matching model from Eclipse-specific rewrite execution. API clients can parse and analyse hint programs in the core module; Eclipse integrations add JDT rewrite operations, editors, markers, quick assists and debug support.

Main programming surfaces

  • Program model: HintFile, TransformationRule, Pattern, RewriteAlternative, GuardExpression and structured-action value types.
  • Parsing: HintProgramParser is the authoritative composite parser for predicates, explicit rule kinds and structured actions. The compatibility HintFileParser remains an implementation layer, not the recommended entry point for complete programs.
  • Matching: PatternIndex, pattern parsers and matchers traverse a compilation unit and retain placeholder bindings.
  • Processing: BatchTransformationProcessor evaluates rules and alternatives and returns typed TransformationResult instances.
  • Planning: SemanticRewritePlan, NodeKey, typed values and relations authorize coordinated changes.
  • Execution: Eclipse-side code converts results into text or structured JDT rewrite operations.
  • Verification: ExecutionTreeSnapshot and ExecutionTreeComparator define framework-neutral runtime contracts.

Module boundary

sandbox_common_core must stay usable without an OSGi runtime. It owns language models, parsing, catalogs, planning, matching and portable tests. The sandbox_common Eclipse bundle owns JDT UI and rewrite integration, runtime action handlers, editors, quick assists, console and debug facilities.

Public versus internal packages

Code intended for general consumption belongs in org.sandbox.jdt.triggerpattern.api. Packages named internal contain implementation details and may evolve with the language. Eclipse runtime SPI packages such as cleanup.actions are exported deliberately but still require the matching Eclipse bundle and JDT APIs.

Fail-closed principle

API implementations must not guess when a stable target, binding, action argument, typed value or relation cannot be established. Return no match, reject the program, or raise a structured diagnostic. Do not authorize a broader node merely because a narrower node became unavailable.
