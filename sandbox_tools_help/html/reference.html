Iterator cleanup: reference status

Runtime contract

The bundle sandbox_tools contains the historical implementation but no longer contributes to org.eclipse.jdt.ui.cleanUps. The id org.eclipse.jdt.ui.cleanup.toolscleanup is owned at runtime by org.eclipse.jdt.ui.

This prevents the same standard cleanup option from instantiating both the maintained JDT implementation and an older Sandbox implementation.

Why the feature remains installable

  • Existing installations receive an update of the same feature and bundle identities, neutralizing the former duplicate registration.
  • The cheat sheet and offline Help remain useful for explaining the transformation.
  • Historical source and tests remain available in the repository for contribution research.

Historical safety model

The retained implementation accepts only canonical traversals. Patterns that remove through the iterator, advance it more than once, expose it, depend on iterator identity, or otherwise cannot be represented by an enhanced for loop are rejected.

These notes describe the archived Sandbox implementation. For current behavior and defects, the Eclipse JDT UI implementation and its tests are authoritative.

Maintenance policy

Sandbox does not promise periodic synchronization with JDT. A comparison should be made only for a concrete research, regression, or contribution need. New production fixes belong upstream.

Support information

Report active cleanup behavior to Eclipse JDT UI. Report only Sandbox packaging, Help, cheat-sheet, or duplicate-registration regressions to the Sandbox project.
