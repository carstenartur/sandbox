Iterator to Enhanced For: reference

Applicability contract

The iterator must represent one collection traversal and must not be manipulated in ways that an enhanced-for loop cannot express.

Safety model

Patterns that call remove(), advance the iterator more than once, expose the iterator, or depend on iterator identity are rejected.

Known limitations

  • This feature currently has no dedicated cleanup configuration tab.
  • Non-canonical loops and simultaneous iterators are not converted.
  • The transformation does not change the collection or iteration order.

Support information

The Help content is shipped with the same feature version as the runtime plug-in. When reporting a problem, include the Sandbox feature version, Eclipse version, Java version, the smallest reproducing source, and whether bindings were available.
