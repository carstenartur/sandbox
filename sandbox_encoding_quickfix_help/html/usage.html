Using Explicit Encoding

Entry point and policy

Open Java > Code Style > Clean Up, edit a dedicated cleanup profile, and select Explicit Encoding (Sandbox). Choose the policy before running the cleanup: Prefer UTF-8, Keep behavior, or Aggregate UTF-8.

One input, three policies

The following excerpts come from the three executable INPUTSTREAMREADER fixtures. The first reader uses the runtime default; the second explicitly requests UTF-8. Imports from java.io and java.nio.charset and the fixtures' full exception-handling code are omitted here. The example wrapper is only for presentation; the contract test compares the two reader declarations and, where applicable, the generated field with the actual fixture sources.

Before, for all three policies

class E1 {
    void example() throws Exception {
        InputStreamReader is1 = new InputStreamReader(new FileInputStream("file1.txt"));
        InputStreamReader is2 = new InputStreamReader(new FileInputStream("file2.txt"), "UTF-8");
    }
}

Prefer UTF-8

This policy deliberately replaces supported platform-default behavior with UTF-8. An explicit supported charset name can also be replaced with its corresponding standard constant.

After

class E1 {
    void example() throws Exception {
        InputStreamReader is1 = new InputStreamReader(new FileInputStream("file1.txt"), StandardCharsets.UTF_8);
        InputStreamReader is2 = new InputStreamReader(new FileInputStream("file2.txt"), StandardCharsets.UTF_8);
    }
}

Use this policy only when adopting UTF-8 is an intended compatibility decision. The first reader changes behavior on systems whose default charset is different. This is not a promise that every encoding-sensitive overload or every Charset.forName(...) expression is rewritten.

Keep behavior

This policy makes the runtime default explicit as Charset.defaultCharset() for supported implicit-default calls. It preserves the charset policy, not the original source text. The explicitly named UTF-8 reader instead uses StandardCharsets.UTF_8.

After

class E1 {
    void example() throws Exception {
        InputStreamReader is1 = new InputStreamReader(new FileInputStream("file1.txt"), Charset.defaultCharset());
        InputStreamReader is2 = new InputStreamReader(new FileInputStream("file2.txt"), StandardCharsets.UTF_8);
    }
}

The selected platform default is not frozen to the charset of the machine running the cleanup and is not silently changed to UTF-8. Unsupported calls remain subject to the safety boundary below.

Aggregate UTF-8

This policy also adopts UTF-8 for supported implicit-default calls, but introduces or reuses a class-level charset constant. The generated references are qualified with their declaring type.

After

class E1 {
    private static final Charset UTF_8 = StandardCharsets.UTF_8;

    void example() throws Exception {
        InputStreamReader is1 = new InputStreamReader(new FileInputStream("file1.txt"), E1.UTF_8);
        InputStreamReader is2 = new InputStreamReader(new FileInputStream("file2.txt"), E1.UTF_8);
    }
}

The larger fixture also preserves other explicitly selected charsets through corresponding fields. Aggregation does not mean replacing all non-UTF-8 input with UTF-8, or collecting every expression that already uses StandardCharsets. Review each supported rewrite and the compatibility decision for implicit-default calls.

Applicability and Java version

The cleanup requires resolved bindings and a supported encoding-sensitive API. It adapts replacements to the project's Java level. Dynamic charset expressions, unsupported overloads, ambiguous constants, and cases where checked-exception or resource-lifetime behavior cannot be preserved are left unchanged.

Review the real execution preview

  1. Run Source > Clean Up... on a small version-controlled selection.
  2. Select every affected file in the execution preview and inspect constructor, import, and exception changes.
  3. Confirm that every platform-default change is intentional for the chosen policy.
  4. Compile and run I/O, serialization, and integration tests before expanding the scope.
