Using Explicit Encoding

Entry point and policy

Open Java > Code Style > Clean Up, edit a dedicated cleanup profile, and select Explicit Encoding (Sandbox). Choose the policy before running the cleanup: Prefer UTF-8, Keep behavior, or Aggregate UTF-8.

Prefer UTF-8

This policy deliberately replaces supported platform-default behavior with UTF-8 and replaces explicit UTF-8 names with the type-safe standard constant.

Before

Reader reader = new InputStreamReader(input);
Charset charset = Charset.forName("UTF-8");

After

Reader reader = new InputStreamReader(input, StandardCharsets.UTF_8);
Charset charset = StandardCharsets.UTF_8;

Use this policy only when adopting UTF-8 is an intended compatibility decision. The source change is not behavior-preserving on systems whose default charset is different.

Keep behavior

This conservative policy modernizes an encoding only when the source already names it explicitly. Implicit platform-default calls remain unchanged.

Before

Reader defaultReader = new InputStreamReader(input);
Charset explicitUtf8 = Charset.forName("UTF-8");

After

Reader defaultReader = new InputStreamReader(input);
Charset explicitUtf8 = StandardCharsets.UTF_8;

Aggregate UTF-8

This policy introduces or reuses the configured class-level charset constant and routes supported UTF-8 uses through it.

Before

Reader first = new InputStreamReader(in1, StandardCharsets.UTF_8);
Reader second = new InputStreamReader(in2, StandardCharsets.UTF_8);

After

private static final Charset UTF_8 = StandardCharsets.UTF_8;

Reader first = new InputStreamReader(in1, UTF_8);
Reader second = new InputStreamReader(in2, UTF_8);

Applicability and Java version

The cleanup requires resolved bindings and a supported encoding-sensitive API. It adapts replacements to the project's Java level. Dynamic charset expressions, unsupported overloads, ambiguous constants, and cases where checked-exception or resource-lifetime behavior cannot be preserved are left unchanged.

Review the real execution preview

  1. Run Source > Clean Up... on a small version-controlled selection.
  2. Select every affected file in the execution preview and inspect constructor, import, and exception changes.
  3. Confirm that every platform-default change is intentional for the chosen policy.
  4. Compile and run I/O, serialization, and integration tests before expanding the scope.
