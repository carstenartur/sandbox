Container cleanup rules

All rules are disabled by default. A transformation is offered only after binding, usage, ordering, aliasing and thread-confinement checks succeed.

Append-only array to list

String[] values = new String[0];
values = Arrays.copyOf(values, values.length + 1);
values[values.length - 1] = value;

For a strictly local, append-only reference array this becomes a mutable List backed by ArrayList. A final return can preserve the original method signature. For example, a local builder initialized from new String[0] publishes its elements with return values.toArray(new String[0]);. The check requires a fresh array with the exact declared element type and simple append values.

Copy-on-write listener snapshots

An opt-in migration for read-mostly listener lists. Registration originally appends under the private list's lock. Notification takes a typed array snapshot under that lock and then calls each Runnable outside the lock. The replacement takes a CopyOnWriteArrayList iterator snapshot and copies the backing array on each registration. Choose this option for infrequent registration. It preserves duplicate callbacks, their order, and the next notification's visibility of registrations made during a callback.

Manually unique list to ordered set

if (!values.contains(value)) {
    values.add(value);
}

For a strictly local list with stable equality and encounter-order iteration, this becomes a LinkedHashSet.

Parallel arrays to a local record sequence

On Java 16 and later, the opt-in rule can replace two local reference arrays with a list of records. Both columns must start empty, grow in lockstep in an enhanced for loop and use the same count when appending a row. The cleanup follows all reads and proves that each paired observation uses an in-bounds index. It keeps row order, duplicates, null components and each component object's identity. Generated records stay inside the method. Earlier source levels, independently exposed columns and unproven index bounds produce no rewrite.

Closed record key index

This opt-in rule indexes repeated first-match scans over a private final list. The list must be populated during construction with fresh records and a generated String accessor must supply the key for every lookup. A LinkedHashMap keeps the first record inserted for a key. Lookups return that same object, including when later records have the same key. A null query returns null on an empty index and throws on a populated index, matching the original loop. Exposed lists, custom accessors, independently observed duplicates and later writes prevent the change.

Execution boundaries

  • LOCAL_SAFE rules are ordinary explicit cleanups.
  • PROJECT_CLOSED rules require coordinated multi-file preview.
  • The closed-source caller-to-parameter migration is registered as PROJECT_CLOSED; it is not exposed as a local cleanup or save action.
  • Unsupported aliasing, positional access, capture, publication or external signatures cause the cleanup to make no change.

Concurrent membership set

This opt-in rule replaces Collections.synchronizedSet(new HashSet<>()) with ConcurrentHashMap.newKeySet() when the private final field belongs to a final top-level class and all Java uses are individually atomic add, remove, or contains calls on non-null String keys. The preview reports escapes, iteration, explicit monitor use and unproven null handling.
