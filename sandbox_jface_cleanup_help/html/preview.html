Reviewing Cleanup changes

Configuration preview and execution preview

The preview shown while editing a cleanup profile is a small, fixed example. It explains what an option can do, but it is not a preview of your project.

After you invoke Source > Clean Up... and continue to the final page, Eclipse creates the real refactoring change. The upper pane lists affected files and named cleanup steps; the lower pane shows the diff for the selected item.

Several named steps in one file

One cleanup can contain independent transformations. JFace API Modernization therefore labels its changes separately, for example Replace SubProgressMonitor with SubMonitor and Replace ViewerSorter with ViewerComparator.

For ordinary local transformations, clear a step's checkbox to omit only that change. The preview diff updates when another step is selected.

Several independently changed files

Running Cleanup on a package or project groups the changes by file. Independent local file changes may be reviewed and deselected separately.

Coordinated migrations are different

Some migrations are proven safe only as one closed component spanning declarations, signatures, and callers. Those coordinated candidates must be selected or rejected as a whole; individual required files or edits are not independent choices. Until the installed product explicitly presents that atomic selection contract, do not use fine-grained deselection for a coordinated project-wide migration.

After review

  1. Select each file or named step to inspect its diff.
  2. Deselect only changes that are documented as independent.
  3. Choose Finish to apply the enabled change tree.
  4. Compile and run the relevant tests. The complete Cleanup operation can also be undone through Eclipse's refactoring undo support.
