Using CSS Cleanup

Configuration and entry point

Open the CSS Cleanup preference page, configure the external tools, then select a .css, .scss, or .less resource and invoke the matching Format ... with Prettier context action.

Representative formatting result

Before

.toolbar{display:flex;gap:8px;color:#333}
.toolbar .item:hover{background:rgba(0,0,0,.08)}

After

.toolbar {
  display: flex;
  gap: 8px;
  color: #333;
}

.toolbar .item:hover {
  background: rgba(0, 0, 0, 0.08);
}

The exact output is determined by the configured Prettier version and options. Stylelint diagnostics are a separate validation result; they do not imply that every finding is automatically rewritten.

Execution and failure behavior

The command is offered only for supported extensions. The Eclipse process must be able to execute the configured Node.js/npx command. Missing tools, invalid JSON options, timeouts, nonzero tool exit codes, and malformed output are reported instead of silently replacing the file.

This command does not use the Java LTK Cleanup preview. Review the editor or version-control diff after formatting, and use Eclipse file history or version control to restore the previous bytes when required.

Recommended workflow

  1. Pin the intended formatter and lint configuration for the project.
  2. Format one file and inspect whitespace, generated syntax, and line-ending changes.
  3. Run the relevant CSS build, browser, or UI tests.
  4. Apply the command to a wider selection only after the tool configuration is reproducible.

Screenshot regeneration

The preference image is generated from a real Eclipse workbench by SandboxHelpScreenshotsSWTBotTest. The deterministic documentation profile suppresses host-dependent tool discovery and never installs or invokes external npm packages merely to take the screenshot.
