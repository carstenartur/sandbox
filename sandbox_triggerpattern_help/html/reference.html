Code Patterns and Hint DSL: reference

Applicability contract

Each built-in cleanup and each hint rule defines its own syntactic and semantic trigger. Rules that cannot be matched or validated are not applied.

Safety model

Generated or mined rules must be reviewed before broad application. LLM inference is optional and must not silently bypass deterministic validation.

Known limitations

  • Rule quality depends on the trigger and replacement constraints encoded in the hint.
  • LLM-backed inference requires explicit provider configuration and may send selected material to that provider.
  • Mining proposes rules; it does not make semantic equivalence proofs.

Support information

The Help content is shipped with the same feature version as the runtime plug-in. When reporting a problem, include the Sandbox feature version, Eclipse version, Java version, the smallest reproducing source, and whether bindings were available.
