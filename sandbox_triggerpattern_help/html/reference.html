Code Patterns and Hint DSL: reference

Execution versus inference

TriggerPattern has two distinct responsibilities:

  • Execution matches built-in or .sandbox-hint rules and applies deterministic source rewrites.
  • Inference proposes new .sandbox-hint rules from commit diffs, working-tree diffs, selected diffs, Java selections, or wizard input. LLM inference is optional.

Applicability contract

Each built-in cleanup and each hint rule defines its own syntactic and semantic trigger. Rules that cannot be parsed, validated, or matched are not applied.

Safety model

  • Generated or mined rules must be reviewed before broad application.
  • LLM output must pass deterministic DSL validation before it is treated as an executable candidate.
  • DSL validation checks the rule contract; it does not prove semantic equivalence of every future source match.
  • Use preview/diff, compilation, and project tests as part of accepting a newly inferred rule.
  • Do not send source material to an external provider unless the repository/project policy permits it.

Input-specific confidence

  • Commit, working tree, or unified diff: contains explicit before/after evidence and is normally the strongest inference input.
  • Java selection: contains only source context and is best treated as a starting point for manual refinement.
  • Wizard: gives the author explicit control over source pattern, guard, replacement, metadata, and validation.

Project targeting

Refactoring Mining asks the user which open project to analyze. Working-tree mining uses the active editor's project for both repository discovery and generated hints. Selected-diff mining uses the active text editor's project, and Java-selection inference uses the selected compilation unit's project. These paths do not intentionally fall back to the first open workspace project.

Long-running analysis

Commit mining uses one bounded, user-visible Eclipse job instead of starting an unbounded group of hidden provider jobs. The view reports completed, active, and queued work. Cancellation stops the active operation and prevents queued commits from starting.

Live project hint files

Project-local .sandbox-hint and compatible .hint files are workspace resources. Creating, editing, moving, deleting, closing, or deleting a project invalidates associated registry state, including embedded guards and fixes, so the current file state is used without a workbench restart.

Credentials and provider availability

An explicit API key is stored in Eclipse Equinox Secure Storage and rendered as a password field. Legacy ordinary-preference credentials are migrated and removed. Environment-variable fallback remains available. If a provider is explicitly selected, that provider must have a matching Secure Storage key or environment credential; an unrelated provider key does not make it available.

User-facing inference failures identify the workflow and failure type without echoing credentials, prompt contents, or provider response bodies. Technical details belong in the Eclipse Error Log.

Known limitations

  • Rule quality depends on the examples and the constraints encoded in the hint.
  • LLM-backed inference requires a configured provider and may send selected source material to that provider.
  • Mining proposes rules; it does not make semantic-equivalence proofs.
  • The screenshot profile deliberately disables external inference, so documentation screenshots prove workflow discovery and deterministic UI state rather than external-provider availability.

Support information

When reporting an inference problem, include the Sandbox feature version, Eclipse version, Java version, the smallest non-sensitive reproducing before/after example, the entry point used (commit, working tree, diff, selection, or wizard), and the DSL validation result. Do not include API keys.
