Code Patterns and Hint DSL: reference

Execution versus inference

TriggerPattern has two distinct responsibilities:

  • Execution matches built-in or .sandbox-hint rules and applies deterministic source rewrites.
  • Inference proposes new .sandbox-hint rules from commit diffs, selected diffs, Java selections, or wizard input. LLM inference is optional.

Applicability contract

Each built-in cleanup and each hint rule defines its own syntactic and semantic trigger. Rules that cannot be parsed, validated, or matched are not applied.

Safety model

  • Generated or mined rules must be reviewed before broad application.
  • LLM output must pass deterministic DSL validation before it is treated as an executable candidate.
  • DSL validation checks the rule contract; it does not prove semantic equivalence of every future source match.
  • Use preview/diff, compilation, and project tests as part of accepting a newly inferred rule.
  • Do not send source material to an external provider unless the repository/project policy permits it.

Input-specific confidence

  • Commit or unified diff: contains explicit before/after evidence and is normally the strongest inference input.
  • Java selection: contains only source context and is best treated as a starting point for manual refinement.
  • Wizard: gives the author explicit control over source pattern, guard, replacement, metadata, and validation.

Known limitations

  • Rule quality depends on the examples and the constraints encoded in the hint.
  • LLM-backed inference requires a configured provider and may send selected source material to that provider.
  • Mining proposes rules; it does not make semantic-equivalence proofs.
  • The command currently named Mine DSL rules from working tree... still analyzes HEAD rather than uncommitted changes and is therefore not documented as a reliable working-tree workflow yet.
  • The explicit API-key preference is pending migration to secure credential storage; prefer environment-variable credentials meanwhile.

Support information

When reporting an inference problem, include the Sandbox feature version, Eclipse version, Java version, the smallest non-sensitive reproducing before/after example, the entry point used (commit, diff, selection, or wizard), and the DSL validation result. Do not include API keys.
