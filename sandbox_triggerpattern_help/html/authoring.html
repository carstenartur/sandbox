Authoring rules from code selections and the wizard

Commit mining is useful when the transformation already happened in Git history. For a rule you are designing now, use a Java selection or the New Hint File wizard.

Generate a rule from a Java selection

  1. Select the Java expression or statement that represents the pattern you want to generalize.
  2. Invoke Quick Assist (Ctrl+1 on common Eclipse key configurations).
  3. Select Generate DSL rule from selection (AI).
  4. Sandbox wraps the selected source as an inference example and runs the shared LLM rule-inference engine in a user-visible background job.
  5. If inference succeeds, Sandbox creates and opens a new .sandbox-hint file in the selected compilation unit's project.
  6. Review and generalize metavariables, guards, imports, and replacement constraints before using the rule broadly.

A single source selection contains less information than a before/after commit or diff. Treat the generated rule as a starting point, especially when the intended replacement cannot be inferred unambiguously from the selected code alone.

If the provider call succeeds but yields no usable DSL rule, Sandbox reports that result instead of leaving the user to infer what happened. Provider and generated-file failures are also reported while technical details remain in the Eclipse Error Log.

Create a rule with the New Hint File wizard

  1. Open File > New > Other... > Sandbox TriggerPattern > Sandbox Hint File.
  2. Choose the target container and file name.
  3. Set optional metadata such as ID, description, severity, Java version, tags, and binding policy.
  4. Select a template or continue to the rule page.
  5. Enter the source pattern, optional guard, and replacement.
  6. Use the live preview and DSL validation result before finishing.

Use AI inside the wizard

When LLM inference is configured, the rule page offers Generate with AI. This uses the same inference engine as commit mining and the editor quick assist; it is not a separate rule language or execution path.

If no LLM is configured, the wizard remains usable for manual rule authoring and offers a link to the shared LLM preferences.

From rule to executable transformation

Saving a valid .sandbox-hint file is only the authoring step. Project-local hint files are watched as workspace resources, so a newly created or edited rule becomes visible to the loader in the same Eclipse session; no workbench restart should be required. Run the corresponding Code Patterns cleanup/quick-fix path on a small version-controlled sample first.

   -- author / infer --> .sandbox-hint
   -- validate -------> valid DSL
   -- execute --------> preview/diff
   -- verify ---------> compile + tests
