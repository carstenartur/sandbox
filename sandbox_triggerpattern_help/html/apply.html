Applying a .sandbox-hint rule

Rule creation and rule execution are separate steps. A mined or authored rule becomes useful only after it has been reviewed, saved, and exercised against representative source.

Apply one matching rule with Quick Assist

  1. Keep the reviewed .sandbox-hint file in the Java project that should use it.
  2. Open Java source that contains a matching pattern and place the cursor inside the match.
  3. Invoke Quick Assist (Ctrl+1 with the default Eclipse key binding).
  4. Choose the proposal contributed by the matching Hint File rule.
  5. Inspect the resulting edit and run the relevant tests.

This execution path is provided by HintFileQuickAssistProcessor. It is different from Generate DSL rule from selection (AI): the AI Quick Assist is an authoring tool that creates a new rule, while Hint File Quick Assist applies an already existing rule.

Apply rules with Source > Clean Up

  1. Open a JDT cleanup profile and select Code Patterns (Sandbox).
  2. Enable Apply transformation rules from .sandbox-hint files.
  3. Select any bundled rule libraries you also want to run. Project-local .sandbox-hint files are discovered independently of those bundled-library choices.
  4. Run Source > Clean Up... on a small version-controlled scope first.
  5. Review the preview/diff before expanding the cleanup to a package or project.

The batch path is provided by HintFileCleanUp/HintFileCleanUpCore. Both the batch and Quick Assist paths use the same TriggerPattern rule model; they differ in interaction and scope, not in the DSL language.
