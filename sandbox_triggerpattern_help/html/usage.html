Workflow guide

Choose the entry point from the information you already have. All AI-assisted entry points converge on the same TriggerPattern DSL and validator.

If you have Git history

Use Refactoring Mining to inspect recent commits and infer reusable DSL rules from Java diffs. Analyze Project... makes the target repository explicit in a multi-project workspace.

If you have current working-tree changes

Open a file in the target Git-backed project and use Sandbox TriggerPattern > Mine DSL rules from working tree.... Sandbox compares committed HEAD with the current filesystem working tree, so both staged and unstaged Java source changes participate. See Working-tree mining.

If you have a before/after diff

Select the unified diff in an editor and use Sandbox TriggerPattern > Mine DSL rule from diff.... This is the most direct path when the intended transformation is already represented by a concrete change. The active editor determines the project where the generated hint is written.

If you only have source code

Select Java code and invoke Generate DSL rule from selection (AI), or open the New Hint File wizard and author the source pattern, guard, and replacement explicitly.

If you already have a hint rule

  1. Review the .sandbox-hint file and its validation result.
  2. Enable the relevant Code Patterns cleanup behavior.
  3. Apply it first to a small version-controlled scope.
  4. Inspect the preview or diff.
  5. Compile and run the relevant tests before expanding the scope.

Project-local hint files are watched for create, edit, move, and delete events, so a saved rule update is visible in the same Eclipse session without relying on a workbench restart.

When inference cannot proceed

AI-only Quick Assist is offered only when an LLM provider is available. Direct mining commands report missing configuration, provider failures, and no-rule results explicitly. The Refactoring Mining view can still load Git history without scheduling AI analysis when no provider is configured.

Important distinction

Inference creates rules; Code Patterns executes rules. Configuring an LLM does not cause background source changes. A provider is contacted only when an AI-assisted inference action is invoked.

Screenshot regeneration

Canonical Help screenshots come from a real Eclipse workbench through SandboxHelpScreenshotsSWTBotTest. The documentation screenshot profile is deterministic and must not contact an external LLM provider.
