Configuring optional LLM rule inference

LLM Rule Inference is the shared inference backend used by commit mining, working-tree mining, selected-diff mining, the Java-editor rule-generation quick assist, and the New Hint File wizard. It proposes TriggerPattern DSL; it does not execute transformations directly.

Configuration page

Open Window > Preferences > Java > LLM Rule Inference.

Provider, model, and credentials

Select the provider and optionally override its model name. Leaving the model field empty uses the provider/environment default. The model value shown here is part of the runtime inference settings; controls that Sandbox cannot honor are not exposed as configurable preferences.

An API key entered in the preference page is stored encrypted in Eclipse Equinox Secure Storage, not in the normal exportable Eclipse preference node. Sandbox versions that previously stored an API key as an ordinary preference migrate that value to Secure Storage and remove the legacy value.

When no explicit credential is stored, Sandbox can read provider credentials from the process environment:

  • Gemini: GEMINI_API_KEY
  • OpenAI: OPENAI_API_KEY
  • DeepSeek: DEEPSEEK_API_KEY
  • Qwen/DashScope: DASHSCOPE_API_KEY
  • Llama: LLAMA_API_KEY
  • Mistral: MISTRAL_API_KEY

If a provider is selected explicitly in Preferences, Sandbox requires the Secure Storage key or environment variable for that provider. An unrelated provider key does not make the selected provider appear available. With no explicit preference, LLM_PROVIDER may select a provider; otherwise Sandbox can auto-detect a supported provider from its API-key environment variable.

What data can leave Eclipse?

When an AI-assisted action is invoked, the relevant code example is sent to the configured provider as part of the inference prompt. Depending on the entry point, that material can be a Java-file commit diff, a working-tree Java diff, a selected unified diff, or code selected/entered in the rule authoring UI.

No LLM call is required to execute an already-authored deterministic .sandbox-hint rule.

Validation boundary

The provider response is converted into a rule proposal and passed through Sandbox DSL validation. Validation protects the parser/execution contract, but it is not a proof that the inferred transformation is semantically correct for every future match.

When no LLM is configured

Manual .sandbox-hint authoring, Hint File Quick Assist, and deterministic Code Patterns cleanups remain available. The Java-selection AI Quick Assist is not offered without an available provider. Direct mining commands explain how to configure the selected provider rather than silently returning, and the Refactoring Mining view can still load repository history without scheduling AI analysis.

Provider failures and successful calls that produce no usable rule are also reported explicitly. Technical errors are recorded in the Eclipse Error Log without placing API keys or prompt contents in the user-facing message.
