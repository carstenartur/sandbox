Using the Headless Cleanup Application

Application id

sandbox_cleanup_application.org.sandbox.jdt.core.JavaCleanup

Recommended check-mode invocation

Use a disposable workspace, import the checked-out Eclipse project, and start with read-only check mode:

eclipse -nosplash \
  -data /tmp/sandbox-cleanup-workspace \
  -application sandbox_cleanup_application.org.sandbox.jdt.core.JavaCleanup \
  --import-project /work/example-project \
  --mode check \
  --scope both \
  --config /work/cleanup.properties \
  --report /tmp/sandbox-cleanup-report.json \
  /work/example-project

The project directory supplied to --import-project must contain an Eclipse .project file. Cleanup inputs must resolve inside the selected workspace after the import.

Expected output

A valid check run that finds two files requiring cleanup writes:

Using configuration file: /work/cleanup.properties
Starting cleanup...
Mode: check
Cleanup done.
Files changed: 2

The process exits with 2. Source files are restored before the application returns.

An invalid input is reported on stderr. For example:

Skipping file outside workspace: /work/other/Outside.java

The process exits with 1, even when another file would require cleanup. --quiet suppresses progress and diff output, not errors.

Exit-code contract

CodeMeaning
0Help was shown; apply completed without errors; or check/diff found no required changes.
1A command-line, configuration, workspace, import, source-processing, refactoring, patch, or report error occurred.
2Check or diff found required changes and no error occurred.

Error code 1 has precedence over change code 2.

CI shell pattern

set +e
eclipse -nosplash \
  -data "$RUNNER_TEMP/sandbox-cleanup-workspace" \
  -application sandbox_cleanup_application.org.sandbox.jdt.core.JavaCleanup \
  --import-project "$PWD" \
  --mode check \
  --config "$PWD/cleanup.properties" \
  --report "$RUNNER_TEMP/sandbox-cleanup-report.json" \
  "$PWD"
status=$?
set -e

case "$status" in
  0) echo "Cleanup check passed" ;;
  2) echo "Cleanup changes are required" >&2; exit 2 ;;
  *) echo "Cleanup execution failed" >&2; exit "$status" ;;
esac

Modes

  • --mode apply: writes cleanup changes. This is the default.
  • --mode check: detects changes, restores every source file, and returns 2 when changes are required.
  • --mode diff: behaves like check mode and additionally prints a unified diff unless --quiet is active.

Inputs and outputs

  • --config <file>: required Java properties file containing Eclipse cleanup option keys.
  • --source <path>: adds another source file or directory; positional paths are also accepted.
  • --scope main|test|both: filters paths by exact directory segments named test or tests.
  • --patch <file>: writes the collected unified diff when check/diff finds changes.
  • --report <file>: writes JSON evidence including mode, scope, timing, processed/changed files, errorCount, and errors.
  • --verbose: prints each processed file and generated output path.
  • --quiet: suppresses progress and diff output while retaining stderr diagnostics.
