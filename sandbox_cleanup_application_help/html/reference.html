Headless Cleanup Application: reference

Applicability contract

Cleanup inputs must be Java-like files in the selected Eclipse workspace. Use --import-project when a checked-out Eclipse project is not already present in that workspace. The cleanup bundles that own the configured option keys must be installed in the application.

Result precedence

  1. Any invocation, configuration, workspace, import, processing, refactoring, patch, or report error produces exit code 1.
  2. Otherwise, required changes in check/diff mode produce exit code 2.
  3. Otherwise the result is exit code 0.

This order prevents a partial failure from being misreported merely as “changes required.” Diagnostics remain on stderr under --quiet.

Dry-run safety

Check and diff modes apply the Eclipse refactoring inside the running workspace, inspect the result, and restore the original bytes in a finally path. A restore or refresh failure is recorded as an execution error.

Scope semantics

Before cleanup starts, the public application wrapper resolves scoped directory roots to deterministic, sorted Java-file arguments. This keeps explicit project roots and explicit source subdirectories consistent.

  • both leaves caller inputs unchanged.
  • main includes src/main and paths without a conventional test-source marker.
  • test includes src/test, src/tests, top-level project test/tests directories, and explicit roots with those names.

When an Eclipse .project ancestor is available, classification is relative to that project root. A workspace ancestor or Java package named test therefore does not reclassify main sources. If a valid scoped directory contains no matching Java files, the run is a successful zero-file run rather than a command-line error.

JSON evidence

The report contains tool/version, mode, scope, timestamps, duration, processed and changed-file counts, the changed paths, errorCount, and collected error messages. A failure to write the report produces exit code 1 but naturally cannot be represented inside that missing report.

Known limitations

  • Cleanup keys must match the installed Eclipse/JDT and Sandbox cleanup bundles.
  • The scope filter recognizes conventional src/test, src/tests, and explicit test/tests roots; pass custom source sets explicitly with scope both.
  • The generated unified diff is review evidence, not a replacement for Git's rename- and binary-aware diff model.
  • The feature has no interactive UI and therefore no SWTBot screenshot.

Support information

Include the Sandbox feature version, Eclipse and Java versions, full application arguments, exit code, stderr, JSON report when available, and the smallest reproducing Eclipse project.
