JUnit Migration

Migrates supported JUnit 3 and JUnit 4 test code to JUnit Jupiter.

This documentation is installed by sandbox_junit_cleanup_feature together with the runtime plug-in. The runtime plug-in does not depend on this Help bundle.

Two execution modes

Strict migration (default)
Applies only transformations whose complete source scope and Jupiter equivalent have been proven. A construct that cannot be migrated safely is left unchanged.
Best-effort migration (explicit opt-in)
Keeps every independently proven transformation even when another construct cannot be migrated. Each unresolved gap remains in the source, is reported with a stable reason code and remediation, and receives a compilable @todo method scaffold. The resulting project may require manual repair before it compiles or its tests run.

What the feature provides

  • Migrates supported JUnit 3 inheritance and JUnit 4 annotations to Jupiter.
  • Provides a separately selectable JUnit Jupiter 5 to JUnit 6 source-compatibility cleanup.
  • Converts supported assertions, assumptions, expected-exception forms, lifecycle annotations, rules, runners, and imports.
  • Preserves the Eclipse JDT UI inherited-test suppression contract by generating unannotated delegating overrides for proven runner/filter/marker shapes.
  • Coordinates source fixtures and their rule users when the complete lifecycle contract is available.
  • Provides a standard JDT cleanup preview before changes are applied.
  • Provides structured planning diagnostics for transformed and rejected candidates.

Where to start

Open Java > Code Style > Clean Up, edit a cleanup profile, and select JUnit Migration (Sandbox).
