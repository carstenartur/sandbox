Ordered source inputs and authored formulas

In Preserve Java behavior, the mathematics adapter can capture one-dimensional primitive integral array reads, final primitive integral fields, and absolute indexed get(int) calls on ByteBuffer, ShortBuffer, CharBuffer, IntBuffer and LongBuffer. Select every involved primitive numeric type.

Each original occurrence is a distinct input. The source operation executes exactly once and in its original order, even if its value becomes unused or the same expression appears twice. Only the captured numbers enter the shared Regelsuche search. No equality of memory reads, non-null receiver, index range, field value or purity of a virtual call is inferred.

final int _mathRead = buffer.get(STRIDE * 2);

The capture retains the original expression, including the spelling of its index formula. The adapter no longer excludes the entire surrounding arithmetic merely because this opaque index contains a constant calculation. It does not fold the formula or change the constant declaration. Constant formulas outside admitted captures retain the existing protection.

Safety boundaries

Array and buffer receivers must be resolved local variables or parameters. A final field may use its original lexical name, an unqualified this, a local receiver, or a type qualifier for a static field. Mutable and volatile fields, nested receiver chains and computed receivers are not admitted. Static field initialization and its exceptions are retained by executing the original field access, not by substituting its presumed value.

Indices can contain primitive integral locals, compile-time constant names, literals, casts, and total arithmetic. Calls, mutation, division, remainder, nested reads and runtime field values in indices remain boundaries. A read which depends on a local produced earlier in the current region starts a new region. Potentially throwing arithmetic, observable writes and control flow also prevent unsafe motion. Relative get(), bulk reads, buffer writes, floating buffers, checked/fallback profiles and helper-body reads require separate support.

Ordered primitive array stores

A simple store such as out[i] = (u & v) | (~u & w) can now include its total primitive calculation in the verified region. The destination must be a local one-dimensional integral array, with an index independent of locals produced in that region. The store remains at its original position and ends the region. Later reads execute after it, even when source and destination arrays are the same object. Carry values used afterwards remain live.

Whole-file analysis tries established regions first. New store regions use the remaining work budget and cannot overlap an already accepted edit.

Compound stores, computed receivers, effectful indices and potentially throwing arithmetic remain boundaries. No equality of memory locations or whole-loop invariant is assumed, and repeated reads are not merged. This supports arithmetic feeding individual limb stores, not a general rewrite of multiword algorithms.

Costs and verification

The existing capture cost assessment charges capture stores, references and conservative peak storage. The unchanged original loads and indices are not counted as savings. Readability may accept a clearer expression which is not a runtime win; runtime and allocation goals keep their existing cost gates. Legacy report names ArrayRead and arrayReads identify this same ordered-capture obligation, including the added field/buffer forms.

JUnit coverage uses resolved JDT bindings, actual extraction and numerical proof, exact source edits and Undo, complete-class compilation, and execution comparisons including null/bounds precedence, repeated/dead reads and buffer state. Whole-project hit counts and measured speedups remain separate evidence; source admission alone does not establish either.
