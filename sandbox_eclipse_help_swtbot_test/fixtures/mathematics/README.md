# Runtime mathematics Help inputs

The four fixtures are generated by `RuntimeHelpFixtureExportIT`, after the
complete production files pass `BouncyCastleRuntimeCorpusIT`. They are not
manually authored before/after suggestions or constant-folding demonstrations.

| Fixture | Original production methods | Preview packaging |
| --- | --- | --- |
| 01-bouncy-castle-md4-choice | MD4Digest.F | Exact original method in an otherwise empty class shell. |
| 02-bouncy-castle-md4-majority | MD4Digest.G | Exact original method in an otherwise empty class shell. |
| 03-bouncy-castle-ripemd-choices | RIPEMD160Digest.f2 and f4 | Exact contiguous span, including unchanged f3 and original comments. |
| 04-bouncy-castle-sm3-functions | SM3Digest.FF1 and GG1 | Exact contiguous span, including unchanged GG0. |

All inputs come from `bcgit/bc-java` at
`c314b9cdffa3958a0eff5344f8fdcdb0181ed830`, under
`core/src/main/java/org/bouncycastle/crypto/digests/`.
`example.properties` records exact method lines, original whole-file and span
hashes, generated qualified whole-file hash, and the hash of the preview shell.
The exporter reruns the real cleanup on each shell and requires byte-for-byte
agreement with the corresponding transformed methods from the whole-file run.

Run `bash qa/math-optimization/runtime-bouncy.sh PINNED_BC_CHECKOUT FRESH_OUTPUT`
to regenerate the source-bound corpus evidence and the `results/help-fixtures/`
inputs. Original Bouncy Castle classes and original upstream tests are compiled
from that same clean checkout, not substituted by stubs. The output includes
applicable whole-file patches, numerical proof/cost receipts, original JUnit
reports, exact Undo and idempotence checks. SHA256Digest is a no-change control.

The native `MathematicsHelpScreenshotsSWTBotTest` uses the existing
`help-screenshots` Maven profile and registered Clean Up wizard. It verifies
exact preview documents, source compilation, Apply and byte-exact Undo before
writing a PNG and provenance JSON. The normal Help merge gate invokes the same
helper. Source fixtures must never be edited to match a failing screenshot.

Settings: INT,LONG; PRESERVE_JAVA; LOWER_ESTIMATED_RUNTIME; 1,000,000 work units;
20,000 states; no checked arithmetic. The preview shell targets Java 17; complete
production inputs and outputs are independently compiled for Java 8. Eclipse
runs on Java 25. Operation reductions are estimates, not benchmark speedups or
machine-level constant-time certification. Legacy digest examples are not
recommendations for new cryptographic applications.

Bouncy Castle's MIT copyright and permission notice is installed at
`sandbox_math_cleanup_help/html/bouncy-castle-license.html`. Generated pictures
must retain their actual code, source attribution and provenance metadata.
