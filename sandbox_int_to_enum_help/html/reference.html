Int to Enum: reference

Applicability contract

The cleanup requires a coherent constant domain and enough resolved usage information to avoid mixing unrelated integers.

Safety model

Open-ended arithmetic, persistence/wire contracts, reflection, native boundaries, or unresolved external uses prevent automatic conversion.

Coordinated preview-selection contract

A project-wide conversion may be proven safe only as a closed set of declaration, signature, caller, comparison, and switch changes. With the pinned optional patched JDT UI host, that set is exposed as one immutable candidate identity and one atomic selection unit.

  • All files and edits required by one candidate are applied together or not at all.
  • Users may independently enable or disable disjoint candidates.
  • The preview does not expose selectable per-file or per-edit children inside an atomic candidate.
  • Host-side validation rejects a partially disabled nested change even when execution is invoked directly.
  • Ordinary local cleanups keep the standard Eclipse preview-selection behavior.
  • The contract does not apply to save actions, which remain single-file.

This selection guarantee is a capability of the pinned optional patched JDT UI product, not of stock Eclipse. The reflective Sandbox bridge remains loadable on an unpatched host, but an unpatched preview must not be described as enforcing atomic candidate selection.

Known limitations

  • Integer values that form a public serialization or database contract require an explicit migration strategy.
  • Arithmetic and bit-mask domains are not ordinary enum candidates.
  • Cross-repository consumers cannot be updated by a workspace-local cleanup.

Support information

The Help content is shipped with the same feature version as the runtime plug-in. When reporting a problem, include the Sandbox feature version, Eclipse version, Java version, the smallest reproducing source, whether bindings were available, and whether the host used the pinned patched JDT UI bundle.
