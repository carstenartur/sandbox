Using Int to Enum

Entry point and scope

Open Java > Code Style > Clean Up, edit a cleanup profile, select Int to Enum (Sandbox), and enable Convert int constants to enum/switch.

Leave Analyze all project source files for coordinated migrations off for a local conversion. Enable it explicitly when a declaration and its callers in other project source files must be planned together. This scope choice is separate from the optional host support for atomic preview selection described below.

Local conversion: constants, signature and calls

This closed local example uses a private parameter and private constants. The migration changes their uses together; merely introducing the enum would leave the old call sites incompatible.

Before

package test1;

public class E2 {
    private static final int STATUS_PENDING = 0;
    private static final int STATUS_APPROVED = 1;
    private static final int STATUS_REJECTED = 2;

    public void run() {
        process(STATUS_PENDING);
        process(STATUS_REJECTED);
    }

    private void process(int status) {
        if (status == STATUS_PENDING) {
            System.out.println("Pending");
        } else if (STATUS_APPROVED == status) {
            System.out.println("Approved");
        } else if (status == STATUS_REJECTED) {
            System.out.println("Rejected");
        }
    }
}

After

package test1;

public class E2 {
    private enum Status {
        PENDING, APPROVED, REJECTED
    }

    public void run() {
        process(Status.PENDING);
        process(Status.REJECTED);
    }

    private void process(Status status) {
        if (status == Status.PENDING) {
            System.out.println("Pending");
        } else if (Status.APPROVED == status) {
            System.out.println("Approved");
        } else if (status == Status.REJECTED) {
            System.out.println("Rejected");
        }
    }
}

Coordinated conversion across two source files

Enable project-wide analysis for this example. Both files are in the same default package, matching the executable fixture. The method and generated enum remain package-accessible; the generic owner does not require a parameterized qualifier for its nested enum.

Before: OrderProcessor.java

public class OrderProcessor<T> {
    static final int STATUS_PENDING = 0;
    static final int STATUS_APPROVED = 1;

    void process(int status) {
        if (status == STATUS_PENDING) {
            System.out.println("pending");
        } else if (status == STATUS_APPROVED) {
            System.out.println("approved");
        }
    }
}

Before: OrderClient.java

public class OrderClient {
    void run(OrderProcessor<String> processor) {
        processor.process(OrderProcessor.STATUS_PENDING);
    }
}

After: OrderProcessor.java

public class OrderProcessor<T> {
    enum Status {
        PENDING, APPROVED
    }

    void process(Status status) {
        if (status == Status.PENDING) {
            System.out.println("pending");
        } else if (status == Status.APPROVED) {
            System.out.println("approved");
        }
    }
}

After: OrderClient.java

public class OrderClient {
    void run(OrderProcessor<String> processor) {
        processor.process(OrderProcessor.Status.PENDING);
    }
}

The regression fixture applies both files, compiles the result, and checks Undo. The Help contract compares these examples with that fixture, ignoring formatting but not signatures, qualifiers, or calls.

Applicability and review

A caller passing an arbitrary int is not covered by the local constant-domain proof. Neither is an additional use that still requires the numeric constant. Do not infer support for persistence formats, wire values, bit masks, or consumers outside the analyzed source scope from these examples.

Run Source > Clean Up... on a version-controlled selection, inspect every changed signature and call site, then compile and run the affected tests. Save actions remain single-file and do not expand to unrelated project files. Project-wide scope must be chosen through an explicit cleanup operation.

Atomic project-wide preview

With the pinned optional patched JDT UI host, every coordinated Int-to-Enum migration is shown as one candidate-level checkbox leaf. Selecting the candidate shows all required Java files and the Selection is atomic explanation. Required file changes and nested edit groups are informative; they cannot be enabled or disabled independently.

  • Enable or disable the whole candidate as one unit.
  • Independent candidates remain independently selectable.
  • A partially disabled nested change is rejected before execution and by direct perform validation.
  • Ordinary local cleanup changes retain Eclipse's normal file-level and edit-group selection.
  • Save actions remain single-file and never enter this coordinated preview path.

The screenshot and candidate-level contract require the pinned optional patched JDT UI product. Stock or otherwise unpatched Eclipse installations can still load the Sandbox cleanup, but they do not provide this host-side atomic-selection guarantee. Do not treat a stock preview as proof that a project-wide candidate cannot be partially selected.

For the distinction between configuration preview, execution preview, independent local deselection, and coordinated atomic migrations, see Cleanup preview model.
