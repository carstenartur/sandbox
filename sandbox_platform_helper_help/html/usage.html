Using Platform Status

Entry point

Open Java > Code Style > Clean Up, edit a cleanup profile, and select Platform Status (Sandbox). The configuration preview shows the supported constructor simplification. The execution preview shows the actual combined source diff for each selected file.

Representative Status transformation

A five-argument Status constructor can be shortened when its severity is supported and its status code is provably IStatus.OK. The explicit plug-in identity is retained.

Before

import org.eclipse.core.runtime.IStatus;
import org.eclipse.core.runtime.Status;

IStatus status = new Status(
    IStatus.WARNING,
    MyPlugin.PLUGIN_ID,
    IStatus.OK,
    "Could not load preferences",
    exception);

After

import org.eclipse.core.runtime.IStatus;
import org.eclipse.core.runtime.Status;

IStatus status = new Status(
    IStatus.WARNING,
    MyPlugin.PLUGIN_ID,
    "Could not load preferences",
    exception);

Why the plug-in identifier is preserved

Status.info(...), Status.warning(...), and Status.error(...) infer a plug-in identifier from the calling class and its OSGi bundle. That inferred value is not necessarily equal to the constructor's explicit String or Class identity. Replacing the constructor with a factory call without proving equality would change IStatus.getPlugin() and could affect logging and diagnostics.

The cleanup therefore removes only the redundant OK code. It does not shift identity verification to the user after an automatic rewrite.

Compile-time code evaluation

Applicability is based on the resolved compile-time integer value rather than the source spelling. These forms are equivalent candidates:

IStatus.OK
0
private static final int OK_CODE = 0;

Nonzero and runtime-computed codes remain unchanged:

APPLICATION_SPECIFIC_CODE
computeStatusCode()
17

MultiStatus

A MultiStatus may carry an application-specific code, so the cleanup never replaces an arbitrary code with IStatus.OK. It may only replace a compile-time numeric zero with the named constant.

Before

MultiStatus status = new MultiStatus(
    pluginId,
    0,
    "Several operations failed",
    exception);

After

MultiStatus status = new MultiStatus(
    pluginId,
    IStatus.OK,
    "Several operations failed",
    exception);

When no change is made

  • The constructed type is not exactly the supported Eclipse Status or MultiStatus type.
  • Type or constant bindings cannot be resolved.
  • The status code is nonzero or is computed at runtime.
  • The severity has no supported mapping, for example IStatus.CANCEL.
  • The constructor is already in the shorter semantics-preserving form.
  • The project does not satisfy the cleanup's current compatibility gate.

Recommended workflow

  1. Enable Platform Status (Sandbox) in a dedicated cleanup profile.
  2. Run Source > Clean Up... on a small, version-controlled selection.
  3. Select each file in the real execution preview and inspect its combined diff.
  4. Confirm that only a redundant OK code is removed or named.
  5. Compile and run status-handling and logging tests before expanding the scope.

Real-corpus evidence

Canonical upstream screenshots must use an exactly pinned local workspace and the same corrected applicability rules as the headless inventory. Nonzero application-specific codes are important negative evidence and must remain unchanged.
