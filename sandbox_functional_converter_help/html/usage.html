Using Functional Converter

Entry point

Open Java > Code Style > Clean Up, edit a dedicated profile, and select Functional Converter (Sandbox).

In Loop Conversion, select Enable bidirectional loop conversions, choose a target format, and enable the source formats to convert. The examples below use Stream (forEach, map, filter) as the target. Each source checkbox is independent.

The other target formats support only their implemented directions: enhanced-for can consume supported stream or iterator loops; iterator-while can consume supported enhanced-for or stream forms. The experimental classic-for source is supported only with the Stream target. A target choice is not a promise that every source shape can be converted.

Older profiles may also contain the separate legacy functional-cleanup switches. Those keep their existing Stream-only behavior and are independent of the bidirectional source selections. Use a dedicated profile without the legacy switches when checking one bidirectional option in isolation.

Simple iteration

Before

for (String name : names) {
    System.out.println(name);
}

After

names.forEach(name -> System.out.println(name));

Filter, map, and ordered terminal action

Before

for (Integer value : values) {
    if (value != null) {
        String text = value.toString();
        System.out.println(text);
    }
}

After

values.stream()
    .filter(value -> value != null)
    .map(value -> value.toString())
    .forEachOrdered(text -> System.out.println(text));

Reduction

Before

int max = Integer.MIN_VALUE;
for (Integer value : values) {
    max = Math.max(max, value);
}

After

int max = values.stream().reduce(Integer.MIN_VALUE, Math::max);

Iterator while-loop

Enable Convert from: Iterator while-loops with the Stream target.

Before

Iterator<String> it = items.iterator();
while (it.hasNext()) {
    String item = it.next();
    System.out.println(item);
}

After

items.stream().forEach(item -> System.out.println(item));

The recognized shape consumes one element per iteration. Iterator removal, multiple next() calls, and loops with an unsupported break are not replaced by an assumed equivalent stream.

Left unchanged: iterator removal

Iterator<String> it = items.iterator();
while (it.hasNext()) {
    String item = it.next();
    if (item.isEmpty()) {
        it.remove();
    }
}

Classic index-based for-loop

Enable Convert from: Classic index-based for-loops (experimental) with the Stream target. This source option is disabled by default. In the bidirectional configuration, disabling it or the master switch prevents this conversion; selecting enhanced-for or iterator-while does not silently produce a stream instead.

Before

for (int i = 0; i < 10; i++) {
    System.out.println(i);
}

After

IntStream.range(0, 10).forEach(i -> System.out.println(i));

The cleanup adds java.util.stream.IntStream when needed. This example is the simple increasing, unit-step, exclusive-upper-bound case; it is not a guarantee for arbitrary bounds, counter writes, labeled control flow, or externally observed loop variables.

Ordinary counter-based while loops, do-while loops, and queue-draining loops are not iterator-loop equivalents and remain unchanged. Review each proposed conversion rather than enabling all directions on the assumption that they are interchangeable.

Safety boundary

The cleanup is intentionally conservative around mutation, side effects, encounter order, exception behavior, variable capture, labeled control flow, and values that escape the loop. A visually similar loop is not enough: the complete binding-resolved source pattern must match a supported transformation. Comments are retained in supported block-lambda forms; unsupported placements cause the candidate to be rejected rather than discarded.

Review the real execution preview

  1. Start with one method or one source file in version control.
  2. Inspect the complete pipeline in Source > Clean Up..., including terminal operation and ordering.
  3. Compare exception timing, side effects, short-circuiting, and result values with the original loop.
  4. Compile and run focused tests before applying the cleanup to a wider selection.

The standard Eclipse file-selection and code-comparison UI is shown in the Cleanup preview model.
