Using PDE XML Cleanup

Entry points

Enable XML Cleanup (Sandbox) in a cleanup profile, or select a supported PDE resource or project and invoke Clean Up PDE XML from its context menu.

Representative formatting result

Before

<plugin>
    <extension point="org.eclipse.ui.views">
        <view
            class="com.example.MyView"
            id="com.example.myview"
            name="My View" />
    </extension>
</plugin>

After

<plugin>
  <extension point="org.eclipse.ui.views">
    <view class="com.example.MyView"
          id="com.example.myview"
          name="My View"/>
  </extension>
</plugin>

When tab conversion is enabled, only structural leading indentation is converted. Attribute values and text content are not rewritten as indentation.

Supported scope and guarantees

The cleanup is restricted to supported PDE descriptors and schema resources in approved project locations, such as project-root metadata, META-INF, and OSGI-INF. It removes redundant whitespace, normalizes formatting, and is expected to be idempotent. XML element structure, attributes, and meaningful text must remain equivalent.

Unsupported resources, malformed XML, mixed-content cases that cannot be formatted safely, and paths outside the PDE scope are left unchanged or reported rather than processed as generic XML.

Recommended workflow

  1. Start with one descriptor in version control.
  2. Run the cleanup or context command and inspect the actual XML diff.
  3. Confirm that only formatting changed and run PDE/schema validation.
  4. Run the operation a second time; a stable result should produce no further diff.

Java cleanup preview screenshots do not represent the direct PDE XML context command. The configuration image shows the cleanup options; the source-control diff is the authoritative result evidence for the selected XML file.
